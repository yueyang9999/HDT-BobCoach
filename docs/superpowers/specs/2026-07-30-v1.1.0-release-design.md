# BobCoach v1.1.0 发布设计

日期：2026-07-30
状态：用户已批准方案 1，授权在验证通过后合并并公开发布

## 1. 发布目标

将已经过用户实机验证的状态提示面板字号调节与拖动功能，连同当前分支内面向 HDT 1.54 的兼容性修复，作为正式功能版本 `v1.1.0` 发布。GitHub、离线安装包、本地夸克上传包、更新日志和安装文档必须使用同一版本身份与同一份构建产物。

## 2. 发布范围

- 将包版本更新为 `1.1.0`，程序集版本更新为 `1.1.0.0`。
- 保持 HDT 兼容基线为仓库当前声明的 `1.54.0.7376`。
- 在 `CHANGELOG.md` 增加 `1.1.0 - 2026-07-30`，说明状态提示面板字号、拖动、位置持久化、默认锁定及相关兼容性修复。
- 更新中文安装说明，增加状态提示面板的设置入口、字号调整、解锁拖动、重新锁定和恢复默认步骤。
- 从用户提供的三张截图生成裁剪、隐私清理、压缩后的文档图片。原图不修改、不提交；最终图片只进入 `docs/user/images/install/` 或 `docs/user/images/features/`。
- 构建 `BobCoach-1.1.0-win-x64.zip` 和对应外部 SHA-256 文件，在 GitHub Release 与本地夸克上传目录使用同一字节内容。
- 合并到 `main`、推送 GitHub，并创建公开的 `v1.1.0` GitHub Release。

## 3. 文档与图片设计

安装说明使用文字作为完整主流程，图片只补充关键位置，确保图片失效时用户仍能完成设置：

1. 在 HDT 中打开“选项 > 插件 > Bob教练设置”。
2. 使用“字体大小”滑块调整状态提示文字，界面即时预览并保存。
3. 勾选“解锁状态面板”，回到炉石窗口后按住提示面板拖到目标位置。
4. 拖动完成后取消勾选，或关闭设置窗口，使面板恢复鼠标穿透。
5. 需要撤销自定义时点击“恢复默认”。

三张图片分别承担入口、设置控件和实际效果说明。裁剪时去除牌组、对局记录和其他与说明无关的用户信息；最长边不超过 1600 px，单张目标不超过 500 KiB，并使用语义化英文文件名。

## 4. 版本与资产一致性

以下位置必须一致声明 `1.1.0`：

- `package.json`
- `release_identity.json`
- `src/BobCoach/BobCoach.csproj`
- `CHANGELOG.md`
- 离线包文件名、包内 manifest、校验文件和 GitHub tag

本地发布目录采用 `E:\HDT-BobCoach-release\v1.1.0\`。该目录属于仓库外发布产物目录，不进入 Git；保留 ZIP、SHA-256 和必要的发布说明，供夸克网盘上传。

## 5. 验证门槛

发布前必须完成并记录：

- 干净依赖恢复与 Release x64 构建。
- `npm test` 全套契约、行为和离线包测试，无失败。
- `tools/build/validate_repository.ps1` 通过。
- 发布身份、精确文件白名单、敏感文件、个人路径、回放数据和大文件检查通过。
- `git diff --check` 无错误。
- 离线 ZIP 可重复构建，外部 SHA-256 与文件内容一致。
- 包内版本、DLL 版本、manifest 和安装说明互相一致。
- 已有用户实机验收记录覆盖字号调整和解锁拖动；发布候选包仍需完成安装脚本的隔离生命周期验证。

任何发布门槛失败都先定位根因并修复，不通过跳过测试、注释错误或降低检查强度发布。

## 6. GitHub 发布内容

Release 标题为 `Bob Coach 1.1.0`，tag 为 `v1.1.0`。发布说明包括：

- 本版本新增与修复摘要。
- HDT 兼容基线。
- 状态提示面板设置入口和安装文档链接。
- 已知限制、隐私说明和数据来源链接。
- ZIP 的 SHA-256。

Release 只上传严格白名单生成的 ZIP 和对应 `.sha256`，不上传原始截图、日志、验证证据、构建缓存或用户数据。

## 7. 异常与回退

- 若完整测试失败，暂停发布，保留分支和候选产物并修复根因。
- 若 GitHub 推送成功但 Release 创建失败，不修改或重写公开历史；修复发布操作后继续使用同一已验证提交和资产。
- 若 Release 资产上传后校验不一致，删除错误的 Release 资产并重新上传同一已验证本地产物，不重新打包造成字节漂移。
- 不删除已有 `v1.0.0` Release，用户仍可按升级与回滚文档恢复旧版本。
