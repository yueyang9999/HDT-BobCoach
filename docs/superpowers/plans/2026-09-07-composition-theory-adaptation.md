# 组合理论 × 游戏规则 × 环境主流 × 胜率证据 — 适配、应用与验证

日期：2026-09-07
配套：`2026-09-07-compositional-reasoning-layer-LLD.md`（架构/L接口本）+ `2026-09-07-compositional-memory-breakthrough-plan.md`（调研）。
本文件把"概率模型(成型率) + 子模/DPP(发散) + 停时(commit)"三个理论组件，按
**游戏规则 → 概率模型输入 / 当前环境主流派系与卡组 → 路线集与先验 / 胜率证据 → 价值与校准**
三维度做实，给实施会话可直接落代码的规格与验证矩阵。数据均为 2026-09-07 实际核对。

## 〇、核心主张（工程落地原则）

- **解析概率模型 = 低成本先验 + 路线剪枝**（每次决策毫秒级，可解释）；
- **确定性模拟器 rollout = 真值确认**（引擎即规则；同 seed 可复现）；
- 关系：先解析估 P(成型)/V，裁掉明显次优路线 → 只对 top-K 发散路线做 rollout 反事实 → 收敛到
  动作。**解析不替代 rollout，rollout 不每路都跑**——这是成本与可信的平衡点。
- 换赛季只需换卡池表/模板，理论组件与机制字段版本无关（AGENTS 数据边界）。

## 一、维度 A：游戏规则 → 概率模型的精确输入（全部已核实）

| 规则 | 参数（本项目数据） | 模型角色 |
|---|---|---|
| 每级卡池份数 | `COPIES_PER_TIER={1:16,2:15,3:13,4:11,5:9,6:7}`（SharedPool.js），法术 10 份 | 超几何分布的 N 与 m(c) |
| 种族过滤 | 对局选 5 族（FORBIDDEN_PAIRS 校验）→ 仅该族+中立进店 | 决定每张候选卡的池成员资格 |
| 商店大小 | `SHOP_SIZES={1:3,2:4,3:4,4:5,5:5,6:6}` | 每刷抽 S 张 |
| 升级费用/窗口 | base=[0,5,7,8,11,11]，折扣=回合递减；标准曲线 T2/T3/T5/T7/T9/T11 + R391 偶数窗口 | 决定路线 T\* 视野：5星核心需到 5 本(≥T7~T8)，6星核心需 6 本 |
| 金币曲线 | 3+T−1 封顶 10（英雄修正另计） | 每回合"试抽"预算 = 剩余金 → 买/刷 权衡次数上界 |
| 三连 | 3 份=金卡；持有 2 份时买第 3 主动合成 | 缺口类型"pair_triple"的抽中条件 = 商店出现第 3 份 |
| 刷新语义 | 刷新把店内未买卡放回池 → 各次刷新近似独立；购买才减池 | P(见 c) 按每次刷新独立估算（近似成立） |
| 对手共享池 | 7 对手同池抽卡；板面在战斗后可观测 | 池计数可部分后验更新（可观测部分扣减） |
| 伤害/生存 | damage=tier+存活星 上限(T4-7=10/T8+=15)；血=生存约束 | commit 停时需加"血线硬约束" |

**一次刷新抽到目标卡 c（池余 m、池总 N、单刷 S 张）**：
`P(见c≥1) ≈ 1 − C(N−m, S)/C(N, S)`；T 次刷新未见 ≈ Π(1−p_t)。多卡集合（如引擎+增幅都缺）用
容斥或直接蒙特卡洛（rollout 兜底）。解析式只算**单缺口发现率**做剪枝。

  - T2(10) / T3(1)
- 每体系的卡组组成 = `comp_strategies.json`（45 套/45 覆盖，368 张角色标签：CORE 214 / ADDON 124 /
  CYCLE 30；字段 status + finalBoardWeight + tier）。→ 缺口卡与其星级直接可得，决定"去哪个池抽"。
- 攻略 `tips[].whenToCommit`（带日期/版本）→ 每体系"启动条件/锁死窗口"先验（如恶魔法术吞噬需
  5-6 星引擎+法术生成器齐才值得锁死）。→ 与"卡池路线(出现率高)+协同路线(英雄配)"等 DivergentPlanner
  路线互为启发。
- **用途**：路线先验 P0(X) ∝ meta tier（T0>T1>…），但**必须被本局池/英雄/已持卡修正**——
  这正是概率模型要做的：meta 先验 × 本局可达性。

| 证据源 | 内容 | 用途与口径 |
|---|---|---|
| 回放语料登记册 | REPLAY_DATA_REGISTRY.md（路径/build/日期/数量） | 同 build 语料条件化统计 P(top4|体系,阶段) |
| V 系列 / C-06~C-11 | 已验证的缺口结论（V3 升6≠胜负/V8 5→6停留−0.63/V12 分值压缩…） | 校准口径：条件化到某阶段才比该阶段；防截断/状态混杂 |
| R710/R711 阵容对位矩阵 | 模拟器对位排名：恶魔112>机械92>元素79>亡灵58>野兽55>鱼人54 | 静态体系强度先验（标注 build 与日期） |

| 用户/引擎基准 | 用户近期 avg~1.3 系、引擎 legacy avg（36.4.2 参考 2.70） | 上/下锚点，仅参照 |

价值函数规格：`V(X) = α·P̂(top4 | X, stage)（同 build 回放条件化） + (1−α)·simMatrix(X)`；
`α` 数据不足时降权；无权威数据维度一律 null→降置信（AGENTS 边界）。**玩家动作=观测非标签**。

## 四、应用规格（落到 LLD 的接口）

1. **ReachabilityEstimator（概率，新组件，先于 CeilingEstimator）**
   - 输入：lobby 种族、当前/可达 tier 窗口（由升级费用+金币曲线推出 T\*）、
     `comp_strategies` 池计数、已持卡（板+手，含金卡）、可观测对手扣减、目标卡集合（CORE 缺口）。
   - 输出：每缺口卡 `P_seen(t≤T*)`、每路线 `P_reach(X|T*)`（多缺口取 min 或联合 MC 采样）。
   - 校准：预测 vs 确定性模拟器同 seed 实际出现率（真值），误差>阈值则降置信。
2. **路线评分与发散保持**
   - `score(X) = P_reach(X) × V(X) − commitCost(X, 血线)`；
   - 发散集 top-K：先按 score 初筛 5~8，再用 DPP（核=共享卡/族重叠相似度 × 质量）
     选 K=2~3 条差异路线；K 受"剩余可刷预算/血线窗口"约束（发散有成本，后期 K↓ 收敛）。
   - commit 停时：`score(首选) − score(次选) > gap_阈值` 或 到达 T\* 或 血线硬约束 → 锁死
     （对齐停时理论；阈值先按对拍标定，不拍脑袋）。
3. **对接 LLD**：Reachability/score 供 `CeilingEstimator`（上限=可达最优路线的 V×P_reach）；
   top-K 路线供 `CompositionPlanner`（缺口→动作）与 P1 ceiling-gap 的 steer 集合。
4. **P1 集成**：ceiling-gap 的 steer 目标 = 评分 top-K 路线（而非手选），让测出来的"缺口"
   就是理论推荐的缺口。

## 六、一个可运行的算例（文档自验证）

目标：T5 升 4 本后（~T7）想锁"恶魔法术吞噬"，缺 1 张 5 星引擎"灰烬腐蚀者"。
- 5 星池：N=Σ5星卡在池余量（种族过滤后）；m=该卡池余(9 − 已被拿份数，含自己/可观测对手)。
- 每回合预算：T7 金 9 → 刷 2 次(2金) + 买留余 7 … 保守每次决策含 S=5(5星店) 的刷新 1~3 次。
- `P(一次刷新见它) ≈ 1 − C(N−1, S)/C(N, S)`；连续 2 回合×2 刷未见 ≈ Π(1−p) → 若 < 阈值 →
  模型输出"P_reach 低"，建议把发散集向共享卡族的高可达成路线（如同族替代引擎）倾斜——这就是
  "根据可达性而不是 meta 硬锁"的破局修正。数值以实际池计数代入（M1 校准）。

## 七、边界与纪律（硬）

- 不发明新赛季卡/权重；数值位 null 降置信（AGENTS Next-Season 政策）。
- 玩家动作=观测非标签；回放先读 REGISTRY、标注 build；混用必须标分布。
- 改动走 ISSUE_TRACKER 闭环 + 代码审查（双向验证误判留帧）+ 单测 + 100% 回归；legacy 零改动。
- 本文档理论/公式为方法依据；实现以 M1~M3 证据为准，证据不足只报 engineering readiness。
