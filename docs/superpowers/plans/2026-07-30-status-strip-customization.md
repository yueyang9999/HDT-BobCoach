# BobCoach 状态提示面板字号与拖动实施计划

日期：2026-07-30
依据：`docs/superpowers/specs/2026-07-30-status-strip-customization-design.md`

## 目标

在不改变提示内容、决策逻辑、战斗阶段显隐及 Power.log 配置助手的前提下，为现有状态提示面板增加 12-28 DIP 字号调节、临时解锁拖动、位置与字号持久化、越界约束、恢复默认和 F10 Status 校准支持。

## 实施约束

- 插件进程只加载一份 `LayoutConfig`，设置窗口、渲染器和 F10 校准共同使用。
- 状态提示根元素稳定复用；内容刷新不得中断拖动。
- 解锁状态不持久化，启动、设置窗口关闭、UI 清空和插件卸载均恢复锁定并释放鼠标捕获。
- 锁定状态保持鼠标穿透，不阻挡炉石操作。
- v9/v10 迁移保留既有有效校准字段，只补新增默认值并规范化新增数值。
- 不修改商店识别、决策引擎、发布身份、CI/CD 或网络行为。

## 阶段 1：纯逻辑与配置迁移

1. 先扩展 `LayoutConfigMigrationBehavior`，覆盖 v9/v10 迁移、字段保留、字号和位置异常值。
2. 新增 `StatusStripLayoutPolicyBehavior`，覆盖字号钳制、排版比例及画布边界。
3. 扩展布局分辨率测试，证明状态位置取自配置并正确缩放。
4. 实现配置 v11、新字段、数值规范化及重基准。
5. 实现不依赖 WPF/HDT 的 `StatusStripLayoutPolicy`。

## 阶段 2：共享配置与 F10

1. 让 `CalibrationOverlay` 接受共享 `LayoutConfig`，保留无参构造兼容现有调用与测试。
2. 补全 Status 方向键偏移与仅位置恢复默认。
3. 让 `GameLayoutCalculator.GetStatusStripPosition()` 使用共享配置字段。
4. 用行为测试验证 F10 Status 与设置面板写入同一组字段。

## 阶段 3：稳定 WPF 面板与设置入口

1. 在 `OverlayRenderer` 中创建并复用状态根元素，只替换行内容与更新样式。
2. 按 `StatusFontSize / 13` 同比缩放字号、行高、内边距和最大宽度。
3. 实现解锁、命中测试、移动光标、鼠标捕获、拖动、丢失捕获和最终保存。
4. 在显示、字号变化和画布尺寸变化时约束边界，并把修正后坐标换回校准坐标保存。
5. 新增轻量非模态设置窗口；滑块实时预览、释放保存，恢复默认同时重置字号和位置。
6. `MenuItem` 单实例打开窗口；关闭、清空和卸载时锁定并解除事件。
7. 保持 `OnButtonPress()` 的 Power.log 助手行为不变。

## 阶段 4：文档和验证

1. 更新用户文档，说明入口、字号、解锁拖动、恢复默认和 F10 兼容。
2. 运行新增行为测试和源码契约测试。
3. 运行 `npm test`、仓库验证、HDT 1.54 Release 构建及 `git diff --check`。
4. 逐项核对规格验收标准；自动化无法证明的 WPF/HDT 实机行为明确列入人工验收。

## 回退边界

本次不删除旧配置字段或改变现有 UI 数据流。若 WPF 交互无法在 HDT OverlayCanvas 上可靠工作，停止在设置入口和交互层，不以独立窗口或全局鼠标钩子扩大范围。
