# 算法进化第一性原理迭代方案(2026-08-21)

> 用户诉求: 算法与玩家选择点偏差过大(实测一致率仅25%), 用户对战可狂虐算法;
> 需要基于回放记录+攻略知识做结构性进化, 晚上谷底期跑大规模拟真测试。

## 一、第一性原理: 战棋决策的本质

从 4 局真实回放逐回合对比(算法推荐 vs 玩家操作)提取的核心事实:

| 维度 | 算法现状 | 玩家实际 | 差距本质 |
|---|---|---|---|
| 回合动作量 | 每回合1个推荐 | 每回合3-8个动作 | 算法是"单动作推荐", 玩家是"整回合运营链" |
| 升级节奏 | T2/T4/T6连续推升 | T2/T4/T7/T8/T11 + 升后继续运营 | 算法升完就停, 玩家升完继续买/刷/卖 |
| 滚雪球 | 无卖弱换强循环 | 买→打→卖→再买(持续) | 算法缺运营循环, 玩家有 |
| 技能协同 | 牛头人局几乎不感知 | 每回合用技能(发现伙伴)+换牌 | 算法缺英雄运营节奏建模 |
| 行动顺序 | 独立评分 | 买→打→卖→买 有序链 | 算法缺动作序列规划 |

**第一性原理**: 战棋强手每回合不是"选1个动作", 而是"执行一条资源最优的运营链"——
买什么、打什么、卖什么、留什么金币、何时升, 是按当前板面/商店/血量/对手/英雄技能
综合编排的一串动作。当前算法是"每回合1个best action", 这是结构性降维。

## 二、迭代方案(按优先级)

### P0: 回合运营链(最大差距, 直接决定"对打能不能赢")
- 目标: 算法从"1个动作"升级为"整回合动作序列"(买→打→卖→刷→升)
- 实现: 现有 StrategySequencePlanner(深度3束宽8)是Shadow路径, 需提升为可见路径;
  或新增 TurnOperatorChain: 按金币预算贪心编排动作序列(买得起的强牌→打出手牌→卖弱换强→余钱刷新→升级判定)
- 数据: 回放玩家动作序列(买→打→卖→买)作为序列模板, 攻略知识(滚雪球/经济节奏)作为约束
- 验收: 推荐从"1个动作"变"2-4步动作链", UI 显示"买X→打X→卖Y→买Z"

### P1: 升级节奏重校准(玩家升级 T2/T4/T7/T8/T11 而非连续)
- 数据: 4局玩家升级回合: T2,T4,T7,T8,T11(间隔 2,3,1,3)——不是连续升
- 现状: R0 期望曲线 T2/T5/T7/T9/T10 连续推升, 与玩家节奏不符
- 修复: 升级后 1-2 回合内不连续推荐升(玩家升完就运营), 除非板面达标

### P2: 卖弱换强循环(玩家买→打→卖→再买的核心)
- 数据: 玩家每回合 1-3 次卖牌(换强), 算法几乎不推卖(怕误伤核心)
- 修复: 板面≥4 且店有更强牌时, 主动推"卖弱→买强"链(R3.5 已有雏形, 增强触发)

### P3: 英雄运营节奏建模(牛头人/辛达苟萨等)
- 数据: 牛头人局玩家每回合用技能+换牌, 算法几乎不感知
- 修复: 英雄策略里加"技能节奏"(每回合技能使用时机与金币预留), 已从 R226 参数扩展

### P4: 大规模拟真测试(晚上谷底期)
- 复用: 279 局重建基础设施(reconstruct279) + 模拟器
- 新增: 玩家风格对战(用真实玩家操作序列做对手, 模拟"被用户狂虐"场景)
- 指标: 一致率(推荐vs玩家)从 25% → 目标 60%+; 模拟对战胜率 vs 玩家风格对手

## 三、执行顺序(今晚)
1. P0 回合运营链(最大收益) → 2. P1 升级节奏 → 3. P2 卖弱换强 → 4. 大规模测试

## 四、风险与防线
- 动作链若过度会"锁死"推荐: 每步独立评分, 序列仅作展示+第一步执行
- 升级节奏改错会退步: 用全量 3348 局回归验证(升级回合分布 vs 玩家)
- 卖弱换强怕误伤核心: R231 记忆保护(核心×0.25/对子×0.35)已就位
