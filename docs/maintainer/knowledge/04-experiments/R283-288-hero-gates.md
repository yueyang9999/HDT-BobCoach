# 实验总结: R283-R288 英雄机制与技能门控(2026-08-22)

## 有效的改进(按幅度排序)

### 1. R285 托奇前期技能门控 —— 最大单次改善(名次 -2.37)
- 问题: highFreq 分支让托奇每回合烧 1 金刷新, 升级仅 1.7 次/局, 终局 2-3 本
- 修复: 前期(<3本 且 <T7)走常规逻辑(剩 1 金才用), 中后期才高频刷
- 证据: HeroPowerModule 注释(真实 T10+ 42 次 vs T1-9 13 次)与 highFreq 分支自相矛盾
- 结果: 60局 名次 6.92→4.55, 前四 16.7%→46.7%, 吃鸡 5%→13.3%, 升级 1.68→3.62/局
- 关键: 升级后技能拿高星才是托奇核心, 前期烧钱=拖垮升级节奏

### 2. R286 钩牙低价值板面门控(名次 -0.70)
- 问题: Bob 13-14.5次/局 vs 真实 10——高本后把强卡换低级卡=净亏
- 修复: canUse 加"板面最低评分 >= 6 时拒绝"(评分=tier*2+atk*0.3+hp*0.3)
- 结果: 60局 名次 4.45→3.75, 前四 50%→63.3%, 吃鸡 8.3%→26.7%
- ⚠️ 事故: 首次插入在 return 之后=死代码(60局无效果); 修正到 return 之前

### 3. R283 欧穆 +2金/升级(名次 -0.18)
- 发现并删除 SimulationEngine 旧硬编码块(避免双倍+4金)
- 60局: 名次 4.05→3.87, 前四 51.7%→61.7%

### 4. R284 阮大师启发式选技能(吃鸡 +6.6pp)
- 随机2候选 + 局势评分(战吼板→battlecry, 低金→gold, 有对子→triple_wish)
- 60局: 名次持平(4.05 vs 4.02), 但吃鸡 11.7%→18.3%, 前四 -6.7pp
- 结论: 吃鸡符合核心痛点, 但前四代价需进一步微调评分

## 否决/回滚的实验

### R287 塔维什 skip_hint —— 数据反直觉否决
- 假设: 技能"移除商店→下战斗发射"发射未实现=纯亏 → 加 skip_hint 禁用
- 60局: on 名次4.25/吃鸡10% vs off 名次4.28/吃鸡18.3%
- 结论: 移除商店牌在模拟器有隐性正面价值(剔除不想要牌→商店重组); 已回滚

### R288 曲奇 cookie 锅 —— 修复暴露负收益, 永久禁用
- 发现 R280 补丁把 cookie 块插进 kaelthas if 内部(嵌套bug)→ 曲奇锅逻辑从未触发
- R288 修复嵌套后 60局: 生效 名次4.42/吃鸡10% vs 禁用 名次3.80/吃鸡28.3%
- 结论: 锅机制在模拟器内负收益(买鱼凑锅扭曲正常选卡, 同 R282 刀油); 永久禁用(条件 cookie_pot_off)
- 教训: R280 的 A/B(5.97→4.17)基于嵌套bug下的假象——修复 bug 后必须重验原 A/B 结论

## 通用教训

1. **插入代码必须确认在控制流可达位置**(return 后=死代码); 修复后必须复跑验证
2. **嵌套 if 是隐蔽 bug 源**: 补丁插入时用锚点行, 若锚点在另一个 if 内部, 新块会被吞入
   → 补丁后必须人工检查花括号配对 + 单测覆盖"其他英雄不受影响"
3. **"正确机制" ≠ "模拟器内正收益"**: 曲奇锅/刀油复制/托奇前期刷新都是机制正确但 A/B 为负
   → 每个英雄机制必须独立 A/B 验证, 不能凭直觉
4. **技能门控模式**: 高频技能英雄若前期价值低, 用"时机门控"(本数/回合阈值)而非"频率节流"
   ——托奇/钩牙/欧穆/阮大师均验证有效; 塔维什反例(有隐性价值)
5. **数据>直觉**: 塔维什 skip_hint 心智判断"纯亏"被 60 局数据否决

## R305-R307 追加(2026-08-22 第七轮: 对手AI强度实验)

- 背景: 用户选择继续提升吃鸡率; 方向=对手AI强度提升(生态真实化→Bob在真实强度下验证)
- R305 对手门槛3.5/4.5: 对手买低质卡变弱→Bob吃鸡36.7%(弱对手红利, 生态失真)否决
- R306 对手刷新2→5: 对手变强→Bob吃鸡13.3%(-10pp), Bob升级限制未解锁(3.03 vs 3.27)否决
- R307 中间门槛4.0/5.0: Bob吃鸡6.7%最差——对手门槛无单调规律(噪声敏感)否决
- **结论**: ①生态真实化与Bob成绩冲突(对手强→Bob真实水平低于刷分) ②对手门槛无单调性
  ③R190'对手保持基线保证Bob评估公平'设计正确 ④提升需Bob侧算法(已验证边界内无新空间)
- 已恢复基线; 栈=R301+R303(counter_tags); Bob吃鸡23.9%为当前架构天花板(接近真实28.1%)
- 教训: '让对手更强'不是提升Bob成绩的路径; 成绩提升只能来自Bob侧真实改进(弱对手红利不可取)
