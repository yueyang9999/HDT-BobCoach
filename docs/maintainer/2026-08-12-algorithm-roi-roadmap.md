# 算法提升 ROI 路线

Date: 2026-08-12
Status: Planning, Phase A/B partially implemented

## 结论

当前算法不适合用“堆更多规则去超越强玩家”的方式继续提升。个人开发条件下，最优路径是：

1. 先做一个低风险、稳定、可解释的“基线教练”。
2. 用离线回放把明显的错误推荐和冲突提示压到最低。
3. 在基线可靠后再逐步加动态路径、转型、反制和个性化。

目标是让水平低于使用者的玩家明显少犯错，而不是让算法短期超越强玩家。

## 为什么当前算法会显得弱

主要根因不是单条规则不准，而是：

- 大量规则和多个子模块各自选动作，缺少一个统一的“本回合主线优先级”。
- 早期 return 和多层微调会让最终推荐失去可解释主线。
- 英雄、机制、饰品、暗赐、回放等每个维度都在加分支，维护成本高，冲突也多。
- 当前验证以“测试不崩”为主，缺少“推荐是否真的安全、是否构成一条合理路线”的验收。
- 对低水平玩家最有价值的“避免致命错误”还没有成为第一目标。

## 第一性原理

低水平玩家需要的不是“和我同等思考”，而是：

- 不花不能花的钱。
- 不在血量危险时强升酒馆。
- 不卖唯一战力牌去买没有明确收益的牌。
- 不因为一张其他种族核心就盲目换家。
- 不在追不上总身材时继续堆普通身材。
- UI 只在算法有较高把握时提示，少而准比多而杂更好。

因此指导系统的价值函数应优先惩罚“明显错误”，再优化“次优动作”。

## 个人开发条件下收益最高路径

### Phase A：安全基线（最高优先级）

目标：把“致命错误推荐率”压到接近 0。

- 动态铸币门控：无钱不买、无免费刷新不刷、升完本后不能形成空场或必死。
- 出售门控：出售必须能支付一个明确目标，且被卖卡不是当前核心/唯一战力。
- 冲突门控：一旦推荐升本，其他高成本动作让位；一旦推荐买核心，升本/刷新让位。
- UI 门控：低置信场景不显示，宁可少提示，不能给出矛盾提示。

这些改动已经在做，应作为每次发布前的固定验收。

### Phase B：单一动态路径层

新增一个 `DynamicStrategyPlanner`，不做几十个分散规则，而是输出：

```text
Stage: Early / Mid / Late
PathScore: 每个可用流派的环境强度 + 投入 + 机会
Mode: Flexible / Commit / Hedge / Pivot / Survival / TradeUp
Priority: BuyCore / Hold / Freeze / Refresh / Level / Counter
```

跨回合使用 `DynamicPathMemory`：

- 记录最近几回合见过的其他流派核心。
- 记录当前已投入主线。
- 只有出现“替代核心 + 三连/多个核心 + 当前主线弱”才进入转型候选。
- 转型不做即时切换，先 Hedge，再 Commit。

### Phase C：离线回放验收

复用现有工具：

- `replay_decision_evaluator.js`
- `replay_snapshot_analyzer.js`
- `global_replay_analyzer.js`
- `firestone_xml_to_snapshot.js`

输出：

- 推荐动作与实际动作的差异。
- 高影响差异：最终名次差且动作方向完全不同。
- 硬约束问题：买不起、升不起、空场出售、冲突推荐。
- 动态路径问题：推荐路线和实际最终阵容偏差过大。

不需要大量玩家对局来发现结构性错误，30 局已足够发现系统 bug。

### Phase D：数据校正

用 Firestone / 社区 meta / 本地回放校正权重：

- 环境 T 级：由公开 meta 数据维护。
- 核心卡：由版本攻略和 Firestone 出现率校正。
- 路径权重：通过回放差异人工确认，不自动上线。

优先使用现有线性评分和规则权重，不引入神经网络。

## 不推荐做的事

- 每帧跑完整 MCTS。
- 为每个英雄和每个机制继续增加孤立规则。
- 先建大规模训练数据再发布。
- 用玩家单局动作作为“最优标签”，因为玩家也会犯错。
- 在算法没有稳定基线前继续扩展 UI 信息。

## 成功指标

短期：

- 硬约束违规推荐为 0。
- 同回合推荐不再互相矛盾。
- 出售推荐必须有明确购买/刷新/升本收益。
- 转型推荐只在满足条件时出现。

中期：

- 回放中高影响错误动作比例下降。
- 低水平用户可理解推荐理由，不需要理解内部评分。
- 主线计划、资源计划、对手反制进入统一日志。

长期：

- 使用更大回放集后，能统计“按推荐走是否改善名次”。
- 不是追求超越单个人，而是持续提高玩家基线水平。

## 下一步执行顺序

1. 完成 `DynamicStrategyPlanner` 纯模块和 `DynamicPathMemory`。
2. 接入决策引擎评分，但不改变可见 UI。
3. 增加离线回放差异报告，输出动态路径字段。
4. 用现有 30 局 Firestone 和最新 `global_*.jsonl` 做第一轮验收。
5. 验收通过后，才把高置信路径提示升级为可见指导。

## 2026-08-13 三局实战反馈

三局完整回放暴露出动态路径层已能避免硬错误，但可见 legacy 推荐仍缺少“当前主线优先级”约束：

- 阿凯局后期主线为野兽，仍推荐普通中立死亡随从。
- 芬利局主动英雄技能替换后的主技能识别错误，导致幸运骰没有提示，T1 经济打法也被持有规则误杀。
- 芬利局 T14 建议出售火车王，对手多中等大身材时机制交换卡保护不足。
- 寄生之魂局三连奖励发现 UI 未显示。
- 芬利局赢家的面包这类持续收益法术未进入前期优先路径。

本轮不继续堆孤立英雄规则，优先修复共享层：

- 主英雄技能选择必须识别芬利技能替换。
- 对手反制卡保护使用对手板面结构，不只看单个超大随从。
- Power.log 权威发现候选直接驱动渲染，减少状态提取竞态。
- 主线已明确时对中立/异族普通购买施加后期惩罚，让刷新/主线核心更优先。
- 对前期持续收益法术增加本地文本规则，同时把暗赐、黄金残片和发动机制留在版本化数据边界内。

这三局不能证明算法效果提升，只用于修复明确的可见逻辑错误。真实验收仍需更多完整回放和 Shadow 对比。

## 2026-08-13 Shadow 跨回合记忆与序列规划

当前进入 Phase B 的工程基础设施层：

- `StrategicMemory` 保存有界核心/对子观察证据和上一计划摘要。
- `SequenceSearchPlanner` 提供确定性、有界、失败安全的 beam search。
- `StrategySequencePlanner` 使用累计模拟状态展开 3 步动作链，并把跨回合证据接入 Shadow 评分。
- `DecisionEngine` 保持 `legacy-v1.1.0` 可见输出不变，仅让 Shadow 候选排序和回放记录使用新计划。
- `global_replay_analyzer.js` 暴露 `strategyObjective`、`strategyPlanHash`、动作链和记忆字段，供后续离线审计。

此阶段只验收工程正确性。新算法继续处于 Shadow，真实对局、300 场景效果接受和权重校准仍处于 `blocked-by-season-data`。
