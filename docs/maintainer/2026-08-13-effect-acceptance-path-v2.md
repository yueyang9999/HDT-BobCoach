# 效果验收路径 v2：分层自动证据栈（提案）

> 日期：2026-08-13
> 状态：**提案**，等待仓库负责人确认后纳入赛季数据契约的执行细则。
> 背景：AGENTS.md 要求效果验收需「≥300 个可信、版本匹配、带标注场景 +
> Shadow 比较 + 人工审查」。单人玩家在赛季内人工标注 300 局不现实。
> 本文以第一性原理重构验收路径：**标注由管线自动化，证据分层获取，
> 不再以单一数字门槛阻塞开发**。

## 第一性原理

效果验收的实质 = 获得「版本匹配的真实状态 + 策略决策 + 结果」三者
构成的证据。三个组件全部可以自动化：

| 组件 | 自动化方式 | 现状 |
|---|---|---|
| 状态 | 插件每局自动捕获 `global_*.jsonl`（已部署捕获增强 DLL） | ✅ 零人工 |
| 结果标签 | Firestone 录像自带 finalRank；自打局插件可记录名次 | ✅ 零人工 |
| 策略决策对比 | 同一批状态喂两个 DLL（legacy vs candidate），确定性比较 | ✅ 工具已建（本提案 L1） |

「300 个带标注场景」= 每个捕获状态（状态+玩家动作+结果）本身就是
自动标注的场景。政策字面不要求人工标注；把标注从人工变为管线即可。

## 分层证据栈

### L1 离线双策略对比（已建成，数小时，0 新对局）

- 语料：30 局 Firestone 真实录像 → 349 状态（版本匹配，自带名次标签）
  + 用户 `global_*.jsonl` 流可随时并入
- 工具：`firestone_to_replay_jsonl.js` → `run_dual_policy.ps1`
  （两个 DLL 分跑同一语料）→ `dual_policy_compare.js`（一致率/
  分歧分类/合法性）→ `majority_vote.js`（3 次多数投票降噪）
- 已产出证据（见 `dual-policy-corpus/runs/L1-EVIDENCE.md`）：
  - 引擎自噪声地板 ≈ 0.6%（未播种 MCTS/战斗 RNG）
  - T35→T36 策略差异不可测（1/349 分歧在噪声带内）
  - 0 加载失败、0 非法推荐
- 候选门限（2026-08-13 已定案，见下「L1 门限定案」）：
  三档框架，默认阈值 99% / 95%，审查触发线 3%。

### L1 门限定案（2026-08-13，负责人确认）

**判断依据（实测）**：
- 自噪声地板（多数投票口径，self-check majority3）：2/349 = 0.57%；
  单跑口径：2-4/349 = 0.6-1.1%。
- 真实近版本策略改动（T35→T36）在 349 状态上只产生 1/349 = 0.3% 分歧
  ——小于地板，说明"分歧率"本身是弱信号，必须结合合法性+分类解读。
- 3% 触发线 ≈ 10 个分歧状态：一个真实策略改动（如 T36 法术历史处理）
  只动 0.3% 状态，因此 3% 足以捕获任何有意义的策略漂移，
  但**不设"分歧即拒绝"**——分歧多不代表差，需人工看分类。

**定案（三档 + 默认阈值）**：

| 档位 | 条件（多数投票口径） | 处置 |
|---|---|---|
| 绿（不劣化） | 一致率 ≥ 99% 且候选硬约束嫌疑 = 0 且候选加载失败 ≤ legacy | 自动通过 L1 |
| 黄（需审查） | 99% > 一致率 ≥ 95%（即分歧率 1%~5%） | 人工审查 divergenceTop 分类 + byRank 分层 + 采纳侧趋势（L2） |
| 红（拒绝/回退） | 一致率 < 95%，或候选出现非法动作/加载失败显著高于 legacy | 候选回退 Shadow，不进入发布链 |

- 99% 的选择理由：多数投票口径下地板 0.57%，99% 一致率 = 允许约
  0.4% 的余量，恰好区分"噪声"与"有意义的微小漂移"；未来语料扩充到
  1000+ 状态后可收紧至 99.5%。
- 阈值随语料规模可调：样本越大置信区间越窄，文档保留调整接口
  （阈值写入 `dual_policy_compare.js` 输出头的建议字段，不硬编码语义）。

### L2 采纳加权结果流（被动积累，无额外负担）

- 每局自动捕获；候选 ≠ legacy 且玩家采纳某一方时，记录采纳侧与名次
- 30-50 局正常游玩即有可用趋势；随赛季持续累积
- 工具：`replay_decision_evaluator.js`（已存在，推荐 vs 实际 +
  finalPlacement 关联）持续喂入 L2 汇总

### L3 模拟器全局 A/B（数小时，可控）

- T40 8 人模拟环境：候选策略经 C# 桥接入，与 legacy 同 seed 同对手
  对抗，快速筛掉明显更差的候选、生成可定向验证的假设
- 注意：模拟器为工程对照，数值强度不可比，只用于排序性过滤

### L4 赛季末最终门（自动采集，无标注负担）

- 300 局 = 正常游玩 300 局（每局自动产生状态+动作+名次）
- 赛季末对全量语料跑 L1 工具 + L2 汇总，作为最终综合报告
- 即使未满 300 局，L1-L3 已提供决策质量证据，不阻塞发布决策

## 与现有政策的衔接

- 不降低任何既有门：硬约束/回归/Shadow 记录/人工审查全部保留。
- 「300 局」从「人工标注配额」重释为「自动采集语料规模」，
  仍是赛季末综合报告的数据底座。
- 新策略在 L1-L3 通过前继续保持 Shadow，`legacy-v1.1.0`（当前为
  T36 部署版 6455BBA7）承担可见推荐与回退——不变。

## 已发现的工程事实（供决策参考）

1. v1.1.0（654A6FFD）无 `GlobalReplayState` API，无法接入 L1 工具链；
   回放类 API 为 T30+ 引入。
2. 当前引擎存在 ~0.6% 级决策自噪声（MCTS/战斗模拟未播种 RNG），
   双策略对比需多数投票降噪；**已立项修复**：`DeterministicRng.cs`
   （splitmix64，继承 Random 兼容现有签名）+ `StableSeeds`
   （从状态/板面派生种子），替换 MCTS rollout、战斗模拟、卡池采样、
   CombatContext fallback 四处未播种 Random。
3. 同版本部署 DLL 五处一致（6455BBA7），可作为统一 legacy 参照。
